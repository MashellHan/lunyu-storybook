## 目标与边界

做成一套有完整索引、可以逐章阅读和点击互动的《论语》绘本。共用可靠的阅读机制，每章有自己的场景和表演编排。

| 每章必须具备 | 可以随内容变化 |
| --- | --- |
| 完整原文、对应拼音 | 场景、季节、时间、构图、道具 |
| 领读、跟读、逐字高亮 | 领读者、跟读者组合、出场位置 |
| 点击角色和原文有反馈 | 动作、角色之间的回应、场景中的可点击物 |
| 暂停、停止后直接自由互动 | 开场、转场和完成动作 |
| 移动端可读、减弱动态、离线能力 | 每章页数、每页句数与阅读节奏 |

用户确认保持当前朗读互动形式，不要求另外编写独立剧情。视觉和互动可以呼应原文，不增加白话说明或替换原文。新篇名、章目属于索引的必要内容；其余屏幕文字继续遵守项目约束。

“一节”在内容库里对应底本的一章；长章再拆为连续绘本页。拆页不改变原文顺序、不省略内容，也不把一个完整章误标成多个原典章节。

## 规模与内容底本

本轮只为估算读取了 [chinese-poetry 的论语数据](https://github.com/chinese-poetry/chinese-poetry/blob/master/论语/lunyu.json)：20 篇、512 章、约 15,917 个汉字，章长中位数 23.5 字，最短 5 字，最长 315 字（《先进》侍坐章）。统计不含标点；下载内容 SHA-256 为 `bc336a3839706377892719db44c48a09794a493190535a42bf1c7d4c4233e96c`。

这是候选数据的统计，不是已完成的学术校勘或最终底本选择。不同底本的分章、异体字和标点会有差异。实施时先固定底本、来源、版本与稳定章号，再用另一可靠版本校对；不混合不同版本的章号。

内容流程：原文校对 → 断句与分页 → 拼音及逐字读音标注 → 角色与场景编排 → 配音、时间轴与素材 → 听检、画面检查 → 可发布。

“子曰”“有子曰”等引语标识也是原文的一部分。现有 demo 没有显示开头的“子曰”；正式全书应按选定底本补齐，既有定稿语音保留，需要的新增片段单独制作。

每章清单至少记录原文、拼音、配音、时间轴、场景、互动、人工校对/听检状态。只有目录条目或未配音的文字，不算该章完成。全书验收以底本的全部章号逐项对账。

## 首页与阅读路径

```mermaid
flowchart LR
  H[动画首页：20篇] --> V[篇内章目]
  V --> C[章节绘本：原文与拼音]
  C --> A[领读与跟读]
  A --> F[自由点击互动]
  A -->|■ 停止| F
  A -->|⏸ 暂停| P[冻结音频与动画]
  P -->|▶ 继续| A
  P -->|■ 停止| F
  C --> H
```

首页建议沿用当前原创插画世界，让孩子看到有动物参与的绘本目录。20 篇用可辨认的封面或场景缩略图呈现，保留篇名与顺序，点击后进入篇内目录。具体构图由首页设计阶段确定。

- 首页只载目录、当前可见封面和少量共享素材。入场和点书有动画，阅读前不自动朗读全部目录。
- 篇内按章号与原文开头定位；为未制作内容提供真实的不可播放状态，不能用首章冒充其他章。
- 每章有可直接访问的静态 URL；返回目录恢复所处篇目。首页、篇目录和阅读页均可通过普通链接访问。
- 章内默认每页 1–3 个适合朗读的短句；长句按语义分段，由内容校对确认。保留完整原文、清晰拼音和翻页控制。
- 平板可以保留大场景与底部句子卡；手机采用场景与文字分区，不整体压缩一张固定宽度画布。
- 目录和控制使用语义化按钮/链接及可访问名称，不能仅靠悬停或手势。

## 如何让章节有变化

每章配置场景、角色、道具、出场顺序、读句时的动作、自由互动和结束动作。视觉差异要体现在构图与行动上；主题相关性由分镜审查确认。

| 原文情境示例 | 场景方向 | 可点击行为方向 |
| --- | --- | --- |
| 学而时习之、有朋自远方来 | 温暖书房、伙伴到访 | 角色轮流读句、相互招呼，保留熟悉的 demo |
| 三人行，必有我师焉 | 林间同行 | 点不同伙伴，呈现不同观察和模仿动作并触发对应读句 |
| 逝者如斯夫，不舍昼夜 | 河岸与日夜变化 | 点落叶或水面，看到流动，再触发对应领读/跟读 |
| 温故而知新 | 书亭与翻书道具 | 点书页回看读句、角色示范与回应 |
| 侍坐等长对话 | 围坐交流、多页连续场景 | 随说话者转移焦点，逐页呈现，完成后逐角色点读 |

这些是编排方向，不是已制作的故事或对白。全文仍按底本呈现；具体动作需避免曲解句意。

建议从少量成熟场景和角色起步，逐篇补充：先用 3 个差异明确的样章验证，再建设约 6–8 套场景基础、8–12 个可重复出现的原创角色、12–16 种交互动作。数量只是首轮容量估计，后续按分镜需要扩展；每章仍需人工编排。

20 篇可以各有封面与场景气质；同一篇中的连续章节检查是否重复使用相同背景、站位、出场和互动。没有必要为每章重新造所有素材，但每章应有可指出的表演差异。长篇只在语义转折处切场景，朗读时保持一个焦点。

## 播放器改造

继续使用原生 HTML/CSS/JavaScript 和 Node 构建。运行时只保留当前篇章的媒体与状态，内容、角色和动作注册信息由构建生成，不引入框架或运行时生成服务。

| 当前实现 | 扩展方式 |
| --- | --- |
| `src/app.js` 的 `SENT`、`SOLO`、`KIDS` 写死 | 章节数据提供句子、角色分工与音频引用 |
| 三句、三张卡、三颗星及固定循环 | 根据当前页句子数生成，进度对应真正完成的句子 |
| 角色 ID 与发声/动作耦合 | 角色资源、声音、动作锚点配置与章节选角分开 |
| 固定书房背景和四个动作 | 保留已有实现，增加小型场景与动作库，通过每章编排使用 |
| 所有媒体内嵌一个页面 | 在线按章/页分包；离线按章内嵌 |
| 文本分别写在 JS 和 TTS 配置 | 共享同一份经校对的内容数据，TTS 配置专管声音与发音规则 |

建议的数据边界：

```text
篇目录：篇号、篇名、章号、章目、封面、制作状态
章节：底本与原文、段句、逐字拼音、分页、读音例外
分镜：场景、角色组合、每句领读/跟读者、道具与动作
媒体清单：语音文件、逐字时间、图片图层、处理版本
```

逐字拼音和音频时间必须能映射回原文位置，标点单独处理。多音字按具体句子和位置标注；当前全局别名回映射只适合首章，不能把其他章节中本来就是“悦”的字也改成“说”。无法可靠对齐的时间轴必须进入校对清单。

剧本用有限的动作顺序与参数表达即可。复用目前 `playClip`、逐字高亮、WAAPI 和中断机制，补齐生命周期管理；当前阶段无需可视化时间线编辑器。

## 停止与暂停

用户明确要求：停止自动流程，直接进入点击互动。暂停只冻结当前位置并允许继续，二者独立。

停止需要统一执行：使旧执行编号失效 → 停止当前音频 → 取消等待、延迟动作及剧本动画 → 清理说话状态、气泡和当前字幕焦点 → 进入自由模式。恢复轻量待机，但不恢复刚取消的表演，也不补发完成星星。

必须覆盖标题、开场、领读、跟读、独读、庆祝和暂停态。标题的异步链也要检查取消状态；取消动画后，`finished.catch()` 后面的代码仍可能执行，不能因此重新调用自动播放。

自由点击先取消上一次点击产生的播放；点角色读其分配内容，点句子执行该句领读/跟读。即使没有先按 ▶，第一次自由点击也要在用户手势中解锁同一个 Audio 元素。切页、离开章节和切后台共用清理规则。

原有试音/生图脚本记录了成功经验；本次《学而》另增加隔离的 `scripts/tts/batch.py`，按已审核条目集、输入指纹、原始结果和失败记录控制A/B批次，保留定稿并禁止自动重试，具体接口见 [批次说明](tts/xue-er-batch-interface.md)。其余篇目仍需先制作并校核各自清单，不能把《学而》的通过结论直接推广到全书。旧 `audition.py` 使用 `requests`，现有 requirements 没有显式列出，准备其环境时应核实依赖。

付费生成前先准备具体样章、提示词、角色、字符数与候选数量，再按项目规则取得授权。原文和拼音先校定再生成；每批新音频需要人工亲耳确认读音、速度与叫声音量。最初分析阶段未执行付费工具；随后获准的《学而》A/B批次已执行，结果见 [真实媒体审查](reviews/xue-er-real-media.md)。

## 性能、离线与 Cloudflare

用户已把离线组合的选择交由代理按性能决定，并确认后续部署 Cloudflare。采用：在线静态站点按章加载；离线整书包包含轻量索引和各章自包含 HTML。

本轮测得 demo 的 30 个正文字，对应领读/齐读/独读音频合计 283,596 字节。仅按每字相同存储比例外推 15,917 字，约 150.5 MB MP3，转为 base64 约 200.6 MB，尚不含标题、共享片段、插画和不同语速的影响。这是估算，不是最终包体报价。

- 在线首页不带章节音频；封面只加载可见部分。共享角色图层缓存复用，进入章节后加载该章文本及首屏媒体。
- 最小实现可先保持每章音频内嵌。长章的首屏等待或内存超过样章预算时，扩展为按页媒体包；通过 fetch 后的 Blob/data URL 交给同一个 Audio 播放，避免直接依赖服务器 Range。首次播放前就绪与手势解锁必须在 Safari 实机验证。
- 在线缓存控制按资源是否带版本区分：版本化媒体可长期缓存，目录和章节入口可及时更新。只预取当前/下一页需要的资源，离开后释放失效的 Blob URL 和动画。
- 离线版每章包含自身图片、脚本、音频与时间轴，直接 file:// 打开，不依赖外部 fetch、CDN 或在线 TTS。整书索引链接到包内各章。
- Cloudflare 构建只发布所需的上线资源；原图、TTS 原始文件和试音候选留在源码/制作资料中。深链有真实静态入口和明确的 404 页面。
- 保留 `wrangler.jsonc` 的 `lunyu-picturebook` 配置。发布前执行构建、`npm test`、`npm run check:deploy`，实际部署另按用户授权执行。

## 推进顺序与完成条件

| 批次 | 交付 | 验证重点 |
| --- | --- | --- |
| 当前：首页与 demo 入口 | 动画索引、可用状态、返回路径、停止进入互动、修复阻断手机使用的布局 | 实际浏览器操作、原有回归、手机与平板截图、离线 |
| 三个代表性样章 | 现有首章、一章不同场景的短章、一章长对话 | 数据驱动、视觉差异、长章分页、音频资源峰值 |
| 《学而》整篇 | 按底本完整覆盖首篇，记录内容/媒体/校对实际耗时 | 连续章节是否重复、制作流程是否稳定、人工听检 |
| 其余各篇逐批完成 | 每批交付可播放、校对通过的完整篇 | 逐篇清单、回归、素材复用和体积 |
